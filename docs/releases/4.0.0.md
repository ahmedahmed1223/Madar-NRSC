# Release 4.0.0

Date: 2026-11-19. One newsroom for several stations.

Built from the client's requirements: stations that coordinate through chat groups, no way to weigh workloads before asking for more staff, unclear output per station, and the need to see who works on what and export each person's record.

## What is new

- **Stations** (`src/shared/stations.ts`). Nothing is fixed to three stations: an administrator adds and removes them in الإعدادات ← «المحطات وبطاقات الإنتاج», may mark one as the main station (the rest are branches) and decides which stations work together. Each user belongs to one station (`User.stationId`), set in the user form; a user without a station is central management.
- **Production cards** (`src/shared/productionCards.ts`, collection `productionCards`). One card travels with an item between stations: what is needed, who owns each step, delivery and air times, the script, links, and an append-only trail. Finishing a step hands the item to the next person with a note of what is complete and what is missing; a blocked step needs a reason and alerts the decision owner.
- **«مهامي»** on the cards screen and the dashboard: my open steps and steps addressed to my station that I can pick up.
- **«متابعة اليوم»** for the chief editor: what airs today, what is ready, late or blocked, why, and who decides.
- **«الأعباء والأداء»** (`src/shared/workload.ts`): open load per station and person in weighted points (step type weight × complexity), compared per person between stations; output per period with a shared item counted once and each station credited for its part; each employee's record with print/PDF and CSV.
- **Shift handover brief** (`src/shared/handover.ts`), written by the platform from the cards: stuck or late, due next, in progress, finished, colleagues' notes. Copy as text or print.
- **Brief drafts**: the assistant (`BRIEF` mode of `/api/v1/ai/copilot`, when `GEMINI_API_KEY` is set) drafts a short on-air brief from the card and lists what is missing to verify. Nothing is saved until a person saves it; approval stays with the responsible editor.

## Rules enforced on the server

- New permissions: `cards.view`, `cards.work`, `cards.manage`, `workload.view`, `workload.view_all`. Existing databases get them once for the system roles that need them (`NEW_PERMISSION_GRANTS`); custom roles are edited in «المستخدمون والصلاحيات».
- Only `cards.manage` creates, edits, closes, cancels or deletes cards and approves scripts. An assignee changes the status, note, blocked reason and time of their own step only; anyone with `cards.work` may pick up an unassigned step addressed to their station (or to nobody) and add notes.
- A supervisor assigns people inside their station's scope: own station, the main station and linked stations. The main station and users without a station assign anywhere.
- Names, stations, start and completion times, the author of every note and the script approval are stamped by the server (`src/server/cards.ts`). Earlier trail entries cannot be rewritten or removed by anyone. A script approval does not survive a change to the text by a non-supervisor.
- `stationId` is a privileged user field: colleagues cannot move themselves between stations, and an unknown station is rejected.
- Editorial tasks get a server `completedAt`, so they count in output per period.

## How work is measured

- Card step: weight of its type (1-10, editable) × complexity (1 simple, 2 medium, 3 complex).
- Outside cards: editorial task 2 points, department request 2 (urgent 4), news story written 2. A story produced through a card is counted by the card only.
- Station level: open points per person compared with the average of the staffed stations: above 1.5× is «حمل مرتفع», below 0.5× «طاقة متاحة».

## Boundaries

- Workload and output are computed in the browser from synced data. News older than `NEWS_ACTIVE_DAYS` (90 by default) is no longer synced, so periods longer than that undercount news written outside cards. Cards, tasks and requests are complete.
- Tasks finished before this release have no `completedAt` and are not counted in period output.
- Station scope limits what supervisors see in «الأعباء والأداء» and whom they may assign. Cards themselves are readable by everyone with `cards.view`: it is one shared newsroom.
- Interview transcription is not part of this release: it needs an audio pipeline and a transcription provider chosen by the client.
- The brief assistant was checked for permissions and its "not configured" answer; it was not exercised against the live Gemini service in this environment (no key).

## Added before release: roles, messaging and the administrator's monitor

### Roles and the screens each role opens

- New system roles for the jobs of a station: `MAIN_STATION_MANAGER`, `STATION_MANAGER`, `DIRECTOR`, `PREPARER`, `MONTAGE`, `QUALITY`, `MONITOR`, `REPORTS_EDITOR`. Existing databases get them once (`ensureSystemRoles`). Custom roles work as before.
- A role may list the screens its holders open (`RoleDefinition.screens`, `src/shared/screens.ts`), edited in the role editor. The sidebar, the unified search and the address bar all ask the same function; a screen outside the list shows a notice instead of the page. The home page, help, What's New and personal alerts stay open to everyone, and the system administrator is never locked out.
- System roles stored before this release receive their default screen list once (`role_screens_defaults`). This changes what existing colleagues see after the upgrade; adjust it per role in «المستخدمون والصلاحيات».
- Screen lists organise the workspace. They are not the security boundary: reading and writing data is governed by permissions, which the server enforces.
- New departments: الرصد والمراقبة (`monitoring`), الجودة (`quality`), التقارير (`reports`), each with a request type, a chat channel and a duty roster; card step types «الرصد والمتابعة» and «مراجعة الجودة».

### Messaging

- «المراسلات» (`src/views/MessagesView.tsx`, rules in `src/shared/chat.ts`): direct conversations, groups owned by their creator, and open channels for the newsroom, each station and each department. Messages carry files (pictures, video, audio, PDF, Office documents; `/api/v1/chat/upload`) and may point at a story, card, bulletin or episode.
- Privacy is enforced by the server's read filter: a direct message reaches its two people; a group message the members at the time it was sent (the server stamps the recipients on the message); a file is served only to its uploader and to people who may read a message carrying it. Messages are immutable.
- Read markers live on the server (`chatReads`, one private row per user) so phone and desktop agree. Private conversations notify once per conversation until read (category `message`, push by default).
- A browser starts with the newest 1,500 messages it may read; older history is fetched per conversation (`/api/v1/chat/history`). Messages follow `LOG_RETENTION_DAYS`; attachments of purged messages are removed by the hourly clean-up.
- The earlier quick drawer in the top bar stays for the open channels.
- Not included: editing or deleting a message, replies/threads, reactions, typing indicators, voice or video calls, and end-to-end encryption (messages are protected in transit by HTTPS and at rest by access to the server; a database administrator can read the database).

### Administrator's monitor

- الإعدادات ← «مراقبة النظام» (`/api/v1/admin/overview`, `system.settings`): what needs attention, storage and free disk space, account states, content counters, periodic jobs with their last run, and active sessions.
- `POST /api/v1/admin/sessions/revoke` (`users.suspend_delete`) signs a user out of every device; audited as `SESSIONS_REVOKED`. Only a system administrator may do this to a system administrator.
- Job runs are kept in memory and start empty after a restart.

### Work done without a connection

- A production-card write based on an older version is merged on the server (`mergeCardChanges`) when the two sides changed different things; the last 50 versions of each card are kept for this. The same field changed on both sides, a closed card or rearranged steps still return the latest version to the sender.

### Typography, sizes and notifications

- IBM Plex Sans Arabic (interface) and IBM Plex Mono (clocks, timecodes) are bundled with the app through `@fontsource` (`src/styles/fonts.css`). No request leaves for a font service, so the look holds on closed networks and offline; the content security policy no longer allows Google Fonts. The offline-air shell keeps its own minimal styling.
- One type scale in `src/index.css`: `text-3xs` 11px, `text-2xs` 12px, `text-xs` 13px, `text-sm` 15px (each one pixel above the previous values, with more leading); 552 ad-hoc `text-[11px]`/`text-[10px]` uses moved onto it.
- The root size is 106.25% from 640px up, and each colleague picks «حجم الخط» for their device (compact, normal, large, larger; `nrcs-text-scale`, applied before first paint by `public/theme-init.js`). Every measure is in rem, so text, spacing and controls scale together. At «أكبر» on a small phone some dense tables scroll sideways, as they do with browser zoom.
- A notification that arrives while the app is open raises a toast with «فتح» (several at once are summarised); a toast holds while it has keyboard focus (not under the pointer, since it may appear over the control being pressed); the countdown bar is now real. The notification centre is a full-width sheet on phones with keyboard-reachable rows. Opening a card or a conversation marks its notifications read, and an urgent message always notifies.
- Messaging switches between one and two panes by the width of the content column (container queries), not of the window. Workload tables keep readable columns and scroll sideways inside a focusable region.
- 196 unused imports were removed across 46 files.

## Third round: storage

- **Dropbox and Google Drive** (`src/server/dropbox.ts`, `src/server/gdrive.ts`, `src/server/storage.ts`): library files are copied in the background into dated folders (`STORAGE_SYNC_SECONDS`, default 20), large files in chunks/resumable sessions, with retries and backoff. The library searches and browses them and brings a file in without copying it; files whose server copy was freed («وفّر مساحة الخادم») are streamed back with byte ranges. Keys stay server-side (meta table or `DROPBOX_*` / `GDRIVE_*` env).
- **Shared folder (SMB)**: colleagues on the station network (configurable CIDR list) may keep a copy in the shared folder. The server writes directly when the share is mounted (`SHARE_DIRECTORY`), otherwise «جسر مدار» (`bridge/madar-bridge.mjs`, Node 20, no dependencies) on a computer inside the network copies files, indexes the folder for search and sends files on demand, all outbound. Token issued once in the settings, stored as SHA-256.
- Only files referenced by a library item or a message are copied; chat files are never copied outside the server. Deleting a library item leaves cloud/share copies as the archive.
- Media library: real clip duration, absolute copied links, where each copy is, video approval limited to approvers on the server.
- Guide: `docs/STORAGE.md`. Tests: `tests/server/storage.test.ts` (fake Dropbox/Drive API; runs the real bridge against a temporary folder).
