# Release 3.28.0

Date: 2026-10-28. Ready for years of intensive use.

Method: a database holding about two years of heavy work was built (6,000 news items with full text, 3,000 tasks, 1,500 guests, 1,000 episodes with rundowns, 1,500 media items, 8,000 activity rows; 44 MB of JSON) and the main screens were measured in a real browser.

- Finding: guests, tasks, episodes and media drew every row at once (87k, 58k, 53k and 48k DOM nodes; 1.2-2.7 s to open a screen). They now draw a page at a time (`src/components/common/ShowMore.tsx`): 3.9k, 2.3k, 2.6k and 2.0k nodes, under a second each. Search and filters still run over the whole list, and exports use the full filtered list.
- Tasks board: open columns list urgent and soonest-due first, the finished column the latest first; each column has its own «عرض المزيد».
- Ctrl+K search results follow the typing (`useDeferredValue`) so the box stays responsive on a large archive.
- Checked and left alone: no idle re-reads of collections, one `/api/v1/data` download per sign-in (an earlier double download was an artifact of rows injected ahead of the server's revision counter), heap stable across screens.
- Known cost at this extreme scale: sign-in to a ready dashboard takes about 2.7 s (1 s download, 1.4 s processing) and `DataStore.get` copies a collection per read (about 180 ms for 6,000 news with full text); the news archive window (`NEWS_ACTIVE_DAYS`) keeps real installations well below this.
- What's New, package, server health and rehearsal report versions match 3.28.0.

Verification: TypeScript, unit tests, production build and the full browser suite on the release commit.
