# Madar NRCS — نظام إدارة غرفة الأخبار وإعداد البرامج

منظومة ويب متعددة المستخدمين لغرف الأخبار التلفزيونية والإذاعية: الأخبار وسير الاعتماد والنشر، البرامج والحلقات والرانداون، الضيوف، المهام، الوسائط، وسجل التدقيق.

- **الواجهة:** React 19 + TypeScript + Tailwind CSS (RTL).
- **الخادم:** Express + **SQLite** (better-sqlite3، وضع WAL) كمصدر وحيد للبيانات.
- **التعاون الفوري:** التعديلات تصل لكل المستخدمين خلال أجزاء من الثانية (Server-Sent Events)، مع كشف التعارض عند تعديل السجل نفسه من مستخدمين، ومحادثة داخلية وقفل بث مباشر مشتركان بين كل المستخدمين.

## التشغيل محلياً (بيئة التطوير)

```bash
npm install
npm run dev          # http://localhost:3000
```

في وضع التطوير تُنشأ بيانات وحسابات تجريبية تلقائياً (`SEED_DEMO_DATA=true`). جميع الحسابات التجريبية تستخدم كلمة المرور `Madar@Demo2026`، مثل:

| البريد | الدور |
|---|---|
| admin@akhbar.tv | مدير النظام العام |
| editor@akhbar.tv | رئيس تحرير |
| journalist@akhbar.tv | صحفي |
| producer@akhbar.tv | منتج برامج |

## النشر في بيئة الإنتاج

### باستخدام Docker (موصى به)

```bash
cp .env.example .env      # عدّل ADMIN_EMAIL و ADMIN_PASSWORD على الأقل
docker compose up -d --build
```

البيانات تُحفظ في الـ volume `nrcs-data` (المسار `/data` داخل الحاوية). يعمل الخادم بمستخدم غير root ويحتوي على فحص صحة `/api/ready`.

### بدون Docker

```bash
npm ci
npm run build
NODE_ENV=production ADMIN_EMAIL=... ADMIN_PASSWORD=... npm start
```

### قائمة التحقق قبل الإنتاج

1. **HTTPS إلزامي:** ضع الخادم خلف Nginx/Caddy/Load Balancer مع شهادة TLS، واضبط `TRUST_PROXY=1`. ملفات تعريف الجلسة `Secure` افتراضياً في الإنتاج.
2. **حساب المدير الأول:** حدّد `ADMIN_EMAIL` و`ADMIN_PASSWORD` (10 أحرف على الأقل بحروف وأرقام). إن لم تحددها ستُولَّد كلمة مرور عشوائية تظهر مرة واحدة في سجل الخادم ويُطلب تغييرها عند أول دخول.
3. **لا بيانات تجريبية:** اترك `SEED_DEMO_DATA=false` (الافتراضي في الإنتاج).
4. **النسخ الاحتياطي:** نسخة تلقائية لقاعدة البيانات كل `BACKUP_INTERVAL_HOURS` ساعة في `DATA_DIR/backups` مع الاحتفاظ بآخر `BACKUP_RETENTION` نسخة. الملفات المرفوعة في `DATA_DIR/uploads` **ليست** ضمن نسخة قاعدة البيانات؛ انسخ مجلد `DATA_DIR` كاملاً دورياً إلى تخزين خارجي.
5. **مثيل واحد:** SQLite يعني عملية كتابة واحدة؛ شغّل نسخة واحدة من الخادم (يتحمل عشرات المستخدمين المتزامنين بسهولة). لا تشغّل عدة نسخ على نفس ملف قاعدة البيانات.
6. **المساعد الذكي (اختياري):** أضف `GEMINI_API_KEY`. بدون المفتاح يعمل المحرر بقوالب ثابتة مع تنبيه واضح.

جميع المتغيرات موثقة في [`.env.example`](.env.example).

## الأمان باختصار

- دخول بكلمة مرور (scrypt) وجلسات httpOnly؛ يُخزَّن في قاعدة البيانات تجزئة رمز الجلسة فقط.
- تحقق بخطوتين اختياري لكل مستخدم عبر تطبيقات المصادقة (TOTP) مع منع إعادة استخدام الرمز، ويمكن للمدير إلغاؤه لمن فقد جهازه.
- رفع ملفات الوسائط يُبث مباشرة إلى القرص مع حد للحجم وقائمة أنواع مسموحة (لا SVG/HTML)، ويُقدَّم لمن سجّل الدخول فقط.
- قفل الحساب مؤقتاً بعد 5 محاولات فاشلة، وتحديد معدل الطلبات لكل عنوان IP.
- **الصلاحيات تُفرض على الخادم** لكل عملية كتابة (لا يمكن تجاوزها من المتصفح)، وسجلات التدقيق غير قابلة للتعديل وتُختم بهوية المستخدم وعنوانه من الخادم.
- حماية CSRF، وسياسة CSP صارمة، وتنقية HTML المعروض (DOMPurify).
- وحدة SQL للقراءة فقط عبر اتصال منفصل، ومعطلة في الإنتاج افتراضياً.
