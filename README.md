# Madar NRCS — نظام إدارة غرفة الأخبار وإعداد البرامج

منظومة ويب متعددة المستخدمين لغرف الأخبار التلفزيونية والإذاعية: الأخبار وسير الاعتماد والنشر، البرامج والحلقات والرانداون، الضيوف، المهام، الوسائط، وسجل التدقيق.

- **الواجهة:** React 19 + TypeScript 7 + Tailwind CSS 4 (RTL)، والبناء بـ Vite 8.
- **الخادم** يعمل بـ Node.js 24 LTS (الحد الأدنى 22.12) وExpress 5. محرك التخزين الافتراضي SQLite، ويتوفر PostgreSQL عند إعداد رابط الاتصال على الخادم.
- **عدة محطات في غرفة واحدة (الإصدار 4):** محطات تُدار من الإعدادات (رئيسية وفروع وارتباطات)، تكليف ترافق المادة بين المحطات، متابعة اليوم لرئيس التحرير، قياس الأعباء والإنتاج لكل محطة وفرد، ملف إنجاز الموظف PDF، وموجز تسليم المناوبة الآلي. وأدوار بصفحات محددة لكل وظيفة، ومراسلات داخلية (مباشرة ومجموعات وقنوات مع المرفقات)، ولوحة مراقبة لمدير النظام. التفاصيل في `docs/releases/4.0.0.md`.
- **التعاون الفوري:** تصل التعديلات إلى الحسابات المخوّلة عبر إشعارات المزامنة (Server-Sent Events)، مع كشف التعارض عند تعديل السجل نفسه من مستخدمين، ومحادثة داخلية وقفل تحكم بالبث المباشر.
- **مساحة عمل شخصية:** من «الرئيسية ← تخصيص عملي» يرتّب الموظف الأقسام التي يحتاجها ويخفي الباقي. الإعداد يحفظ مع حسابه بعد المزامنة. «ملاحظاتي» دفتر خاص بالحساب للكتابة والبحث وتثبيت الملاحظات.
- **الخدمات المساندة وسير العمل:** اختر «الخدمات المساندة» عند إعداد حساب السائق أو موظف الدعم، ثم أسند المهام والخطوات إليه بالاسم. تعرض شاشتا «المهام» و«التكليفات» عمله حسب اليوم أو الأسبوع أو الشهر. تقيس المهام وقت التنفيذ النشط والوقت المنقضي، وتعرض التكليفات وقت العمل المسجّل والانتظار بحسب سجل خطواتها. يضبط مسؤول النظام قواعد المراجعة وسبب التعطل وإعادة الفتح من «الإعدادات ← الإنتاج ← سير عمل المهام والتكليفات».
- **متابعة القسم.** عيّن رئيس القسم في «الإعدادات ← الأقسام الإدارية» واربط الموظفين بالقسم في إعدادات حساباتهم. تعرض «متابعة الفرق والتكاليف ← أعمال فريقي» مهام الموظفين وخطواتهم ومواعيدها وحالاتها، وتتيح شاشة «المهام» لرئيس القسم إدارة مهام فريقه ضمن نطاق الأقسام والمحطات المحددة.
- **الجاهزية للبث:** تُعرض موانع النشرة قرب رأس الصفحة، ويمكن الانتقال إلى القصة المعنية من الرانداون أو وضع الهواء. يوضح العرض مصدر حالة البث، والاتصال، وكيف يُستكمل العمل عند استخدام حزمة الهواء المحلية.
- **الوسائط في الميدان:** يستطيع رفع الملفات الكبيرة استئناف الأجزاء المؤكدة عند انقطاع الشبكة من شاشة الرفع المفتوحة. يبدأ رفع جديد عند إعادة تحميل الصفحة أو إعادة تحديد الملف. يستمر مسار الرفع المعتاد للنسخ المباشر إلى المجلد المشترك.

## أبرز ميزات 4.4

- **التحرير.** تصنيفات متداخلة وفلاتر تشمل الفروع، تنبيهات شخصية لكلمات الأخبار، ودليل أسلوب باقتراحات قابلة للتطبيق. تُنسخ حزمة النشر الرقمي أو تُنزّل بعد اعتمادها.
- **التغطية والهواء.** غرفة عمليات للتغطية، ومتابعة فجوات المناوبات والضيوف، وتوجيهات داخل شاشة الاستديو، وجدار عرض صامت لغرفة الأخبار. يحفظ أرشيف البث النصوص والنتائج ويغذّي تقارير نسبة البث.
- **الوسائط والضيوف.** روابط أحادية الاستخدام للرفع والفحص الذاتي، ونقاط دخول وخروج للوسائط، وحقوق استخدام قابلة للمراجعة، وتفريغ عربي بالتوقيت عند إعداد Azure Speech.
- **المراسلات.** أنشئ من رسالة مسودة خبر أو تكليفاً أو طلب قسم بحسب صلاحيتك. تُستخدم مراجع مرفقات محمية عند إدراج الملفات في العمل الجديد.

تجد خطوات الاستخدام في [دليل الاستخدام](docs/USER_GUIDE.md)، وتفاصيل التحديث في [ملاحظات الإصدار 5.0.2](docs/releases/5.0.2.md) و[ملاحظات الإصدار 4.4.1](docs/releases/4.4.1.md).

## التشغيل محلياً (بيئة التطوير)

```bash
npm install
npm run dev          # http://localhost:3000
```

في وضع التطوير تُنشأ بيانات وحسابات تجريبية تلقائياً (`SEED_DEMO_DATA=true`). جميع الحسابات التجريبية تستخدم كلمة المرور `Madar@Demo2026`، مثل:

|---|---|
| admin@akhbar.tv | مدير النظام العام |
| editor@akhbar.tv | رئيس تحرير |
| journalist@akhbar.tv | صحفي |
| producer@akhbar.tv | منتج برامج |

## النشر في بيئة الإنتاج

### باستخدام Docker (موصى به)

```bash
cp .env.example .env
```

اضبط عنوان HTTPS وبيانات المسؤول، وولّد قيمتين مختلفتين لـ `MADAR_POSTGRES_PASSWORD` و`MADAR_POSTGRES_ADMIN_PASSWORD` باستخدام `openssl rand -hex 32`. ثم شغّل صورة التطبيق مع PostgreSQL 19.

```bash
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up -d --build --wait
```

تستخدم الصورة PostgreSQL افتراضيًا في التثبيت الجديد. إذا كانت لديك قاعدة PostgreSQL خارجية، اضبط `POSTGRES_URL` وشغّل ملف Compose الأساسي. يبقى تثبيت SQLite القائم على قاعدته في `DATA_DIR`. [دليل تشغيل الصورة](/docs/PRODUCTION_OPERATIONS.md#database-engine-selection-and-switching)

البيانات تُحفظ في الـ volume `nrcs-data` (المسار `/data` داخل الحاوية)، والنسخ الاحتياطية الكاملة في volume منفصل `nrcs-backups` (`/backups`، ويُفضّل ربطه بقرص آخر). يعمل الخادم بمستخدم غير root ويحتوي على فحص صحة `/api/ready`، وسجلات Docker محدودة الحجم (`max-size`).

**المنفذ والوكيل العكسي:** يربط `docker-compose.yml` المنفذ على `127.0.0.1:3000` فقط، فلا يصل إليه أحد من الشبكة مباشرة. ضع أمامه وكيلاً عكسياً بشهادة HTTPS (مثال Caddy معلّق في الملف) واضبط `TRUST_PROXY=loopback` للوكيل على الجهاز نفسه، أو `TRUST_PROXY=1` للوكيل في الحاوية المجاورة مع إزالة ربط المنفذ. **لا تضبط `TRUST_PROXY` والمنفذ مكشوف للشبكة**: يستطيع أي أحد تزوير `X-Forwarded-For` وتجاوز حدود محاولات الدخول وتزوير العناوين في سجل التدقيق. ودون HTTPS لا تعمل كوكي الجلسة الآمنة (`COOKIE_SECURE=true`) فيفشل الدخول من أجهزة الشبكة.

### بدون Docker

```bash
npm ci
npm run build
NODE_ENV=production ADMIN_EMAIL=... ADMIN_PASSWORD=... npm start
```

### قائمة التحقق قبل الإنتاج

1. **HTTPS إلزامي:** ضع الخادم خلف Nginx/Caddy/Load Balancer مع شهادة TLS، واضبط `TRUST_PROXY` فقط حين يمر كل الطلبات عبر الوكيل (انظر أعلاه). ملفات تعريف الجلسة `Secure` افتراضياً في الإنتاج، و`COOKIE_SECURE=false` يظهر تحذيراً في السجل و«مراقبة النظام».
2. **حساب المدير الأول:** حدّد `ADMIN_EMAIL` و`ADMIN_PASSWORD` (10 أحرف على الأقل بحروف وأرقام). عند ترك كلمة المرور فارغة يولّد الخادم كلمة مرور عشوائية ويكتبها مرة واحدة في سجل بدء التشغيل. اختر **بدء إعداد النظام** من شاشة الدخول، ثم سجّل الدخول وغيّر كلمة المرور الأولى. احذف `ADMIN_PASSWORD` من `.env` بعد ذلك. لإعداد حساب المسؤول في المتصفح على قاعدة جديدة، اترك `ADMIN_PASSWORD` فارغاً، وعطّل البيانات التجريبية، واضبط `INSTALL_SETUP_TOKEN` على رمز خاص تولّده بأمر `openssl rand -hex 32`. أدخل الرمز في شاشة الإعداد واحذفه من البيئة بعد إنشاء الحساب.
3. **لا بيانات تجريبية:** اترك `SEED_DEMO_DATA=false`. مع `NODE_ENV=production` يرفض الخادم الإقلاع بـ `SEED_DEMO_DATA=true` إلا إذا ضُبط `ALLOW_DEMO_IN_PRODUCTION=true` (لخادم عرض فقط)، ويحذّر من أي حساب ما زال يستخدم كلمة المرور التجريبية.
4. **النسخ الاحتياطي:** كل `BACKUP_INTERVAL_HOURS` ساعة، ومن زر «نسخة احتياطية كاملة الآن» في «قاعدة البيانات»، تُنشأ النسخة الكاملة نفسها: لقطة القاعدة وحزمة فيها الملفات المرفوعة وملخص SHA-256، تُنسخ إلى `BACKUP_DIRECTORY` (المجلد `/backups` في compose) و`BACKUP_REMOTE` إن ضُبطا، مع الاحتفاظ بآخر `BACKUP_RETENTION` نسخة. تنزيل نسخة أو ملف القاعدة يطلب إعادة تأكيد الهوية ويُسجَّل في سجل التدقيق. «تصدير بيانات العمل الحالية (JSON)» في الإعدادات ليس نسخة احتياطية.
5. **الاحتفاظ بالبيانات:** تنظيف تلقائي كل ساعة: سلة المحذوفات بحسب مدة كل نوع في «الإعدادات ← البيانات»، مع افتراضي الخادم `TRASH_RETENTION_DAYS` (30 يومًا)، الإشعارات بعد `NOTIFICATION_RETENTION_DAYS` (90، والمقروءة بعد 30)، سجل النشاط والمحادثة بعد `LOG_RETENTION_DAYS` (365)، وسجل التدقيق الأمني لا يُحذف إلا إذا ضُبط `AUDIT_LOG_RETENTION_DAYS`. القيمة 0 تعني الاحتفاظ دائماً.
6. **برقيات الوكالات:** أضف رابط خلاصة RSS/Atom لأي مصدر من «الإعدادات ← وكالات ومصادر الأخبار» (زر RSS، مع اختبار الرابط). يجلب الخادم البرقيات كل `WIRE_POLL_MINUTES` دقائق إلى «مكتب برقيات الوكالات» ويحتفظ بها `WIRE_RETENTION_DAYS` أيام، ويحوّلها الصحفي إلى مسودة خبر بنقرة. النصوص تُحفظ نصاً خالصاً، والروابط الداخلية محظورة ما لم يُضبط `WIRE_ALLOW_PRIVATE_HOSTS=true`.
7. **أرشيف الأخبار:** الأخبار المنتهية (منشورة، مؤرشفة، مسحوبة، مرفوضة) التي لم تُعدّل منذ `NEWS_ACTIVE_DAYS` يوماً (90 افتراضياً) تُستعرض من زر «الأرشيف القديم» مع بحث عربي مفهرس. يستطيع المحرر إعادتها إلى غرفة الأخبار للتعديل. تجمع صفحة «التقارير» إحصاءات الأخبار النشطة والمؤرشفة من الخادم، وتستخدم لوحة القيادة نافذة الأخبار المتزامنة.
8. **الوضع الليلي والنهاري:** زر في الشريط العلوي وشاشة الدخول؛ يتبع إعداد الجهاز حتى يختار المستخدم، ويُحفظ الاختيار في المتصفح. الألوان الليلية مولّدة من `scripts/generate-dark-theme.mjs` إلى `src/styles/theme-dark.css`، والعناصر الداكنة بطبيعتها تُعلَّم بالصنف `theme-fixed`.
9. **مثيل واحد.** شغّل مثيلًا واحدًا من التطبيق لكل قاعدة نشطة. يوضح [تقرير التشغيل](docs/OPERATIONS_REVIEW.md) نتائج قياس SQLite لخمسين حسابًا تجريبيًا عبر أربع محطات.
10. **المساعد التحريري الذكي**. ضع مفتاح أحد المزوّدين في بيئة الخادم باستخدام `GEMINI_API_KEY` أو `OPENAI_API_KEY` أو `OPENROUTER_API_KEY`. يوضح `.env.example` أسماء متغيرات النماذج واختيار المزوّد الافتراضي. يظهر كل مزوّد مفعّل في قائمة المساعد. يختار المحرر الصياغة أو التدقيق أو اقتراح الأفكار والأسئلة والضيوف ثم يراجع الناتج قبل استخدامه.
11. **تنبيهات البريد والجوال (اختياري):** اضبط `SMTP_HOST` و`SMTP_USER` و`SMTP_PASS` و`MAIL_FROM` لإرسال البريد، و`APP_URL` برابط النظام (HTTPS) لتعمل روابط البريد وتنبيهات الجوال (Web Push). مفاتيح VAPID تُولَّد تلقائياً وتُحفظ في قاعدة البيانات إن لم تحددها. اضبط `TZ` بمنطقة المؤسسة الزمنية (مثل `Asia/Riyadh`)؛ ساعات الهدوء في «تنبيهاتي» تتبع المنطقة الزمنية للمحطة في الإعدادات.
12. **التخزين والنسخ المتعددة.** حافظ على مجلد `DATA_DIR` الدائم وملفات البيئة عند التحديث. SQLite في وضع WAL يتطلب قرصًا محليًا، ويحتفظ PostgreSQL بالسجلات في خادم القاعدة فيما تبقى الملفات والنسخ الاحتياطية وملف اختيار المحرك في `DATA_DIR`. يعرض `/api/ready` جاهزية الخادم والقاعدة. [دليل التشغيل](docs/PRODUCTION_OPERATIONS.md)

### إدارة إتاحة الوحدات ومحرك البيانات

يستطيع مدير النظام إتاحة البرامج والتكليفات للجميع، أو لأدوار وحسابات محددة، أو تعطيل كل وحدة. تُطبّق الإتاحة مع صلاحيات الدور وتبقى سجلات الوحدة قابلة للاستخدام عند تفعيلها مجددًا.

يمكن لمدير القاعدة جدولة الانتقال بين SQLite وPostgreSQL من معالج الإعداد أو شاشة «النسخ الاحتياطي وقاعدة البيانات». يتطلب PostgreSQL تعيين `POSTGRES_URL` على الخادم. يتحقق مدار من السجلات والمرفقات عند تشغيل الخادم التالي ويُبقي القاعدة الأصلية متاحة عند الإخفاق. [خطوات التشغيل](docs/PRODUCTION_OPERATIONS.md#database-engine-selection-and-switching)
13. **معالج الإعداد والبيانات التجريبية.** عند أول دخول بصلاحية إعدادات النظام يفتح المعالج لمراجعة المؤسسة والتوقيت وحساب المسؤول. يمكنك إنشاء مسؤول مؤسسي أو متابعة الإعداد بحساب الإدارة الحالي. إذا بدأت بحساب مدير عام تجريبي وتريد حذفه، أنشئ مديراً عاماً مؤسسياً وسجّل الدخول به أولاً. تعرض «الإعدادات ← البيانات» أمثلة نسخة العرض المتاحة للحذف، وتتيح «فتح معالج الإعداد» بعد حذفها. يمكن أيضاً الرجوع إليه من «المساعدة ← الإعداد السريع للنظام».

14. **كلمات المرور المؤقتة:** ما يصدره المدير من «المستخدمون والصلاحيات» يفتح شاشة تغيير كلمة المرور فقط (الخادم يرفض أي عمل آخر برمز `PASSWORD_CHANGE_REQUIRED`)، وينتهي بعد `TEMP_PASSWORD_HOURS` ساعة (72 افتراضياً) إن لم يُستخدم. لكل مستخدم 10 أجهزة على الأكثر؛ يُنهى أقدمها تلقائياً.
15. **تحذيرات النشر:** عند الإقلاع وفي «الإعدادات ← مراقبة النظام» يحذّر الخادم من `COOKIE_SECURE=false` وغياب `APP_URL` أو `TZ` والحسابات على كلمة المرور التجريبية.

جميع المتغيرات موثقة في [`.env.example`](.env.example)، والتشغيل اليومي في [`docs/PRODUCTION_OPERATIONS.md`](docs/PRODUCTION_OPERATIONS.md).
تضبط `AI_DAILY_REQUESTS` و`AI_DAILY_REQUESTS_BY_ROLE` عدد محاولات الاتصال اليومي بالمزوّد لكل حساب. يستعرض المحرر الفرق قبل تطبيق المقترح، ويتاح اختيار حجب المادة الحساسة عن المزوّد.
توضح [مراجعة التشغيل والأداء](docs/OPERATIONS_REVIEW.md) نتائج قياس SQLite، وترقية النسخ الاحتياطية، والتحقق من صلاحيات الملفات والإجراءات.
تغطّي [مراجعة النظام](docs/SYSTEM_REVIEW_4.2.2.md) نتائج خط الأساس، ويشرح [دليل الاستخدام](docs/USER_GUIDE.md) الوصول إلى الملاحظات وتخصيص صفحة العمل.

### تفريغ الوسائط وروابط فحص الضيف

- لتفعيل طلب التفريغ العربي يدوياً، اضبط `MEDIA_TRANSCRIPTION_AZURE_REGION` و`MEDIA_TRANSCRIPTION_AZURE_KEY`. يرسل الطلب الصوت إلى منطقة Azure Speech المضبوطة. استخدم `MEDIA_TRANSCRIPTION_FFMPEG` لتحديد FFmpeg على الخادم واستخراج الصوت من الفيديو. لتفعيل التفريغ التلقائي للرفعات المؤهلة، اضبط `MEDIA_TRANSCRIPTION_AUTO=true`.
- اضبط `APP_URL` على عنوان HTTPS الذي يستطيع الضيف فتحه، وهيّئ SMTP لإرسال روابط الفحص بالبريد. يفعّل `GUEST_TECH_AUTO_EMAIL=true` إرسال الفحص قبل الهواء للضيوف المؤهلين. يمكن للمشغّل إنشاء الرابط ومشاركته يدوياً من الحلقة أو قصة النشرة.

## الأمان باختصار

- دخول بكلمة مرور (scrypt) وجلسات httpOnly؛ يُخزَّن في قاعدة البيانات تجزئة رمز الجلسة فقط.
- تحقق بخطوتين اختياري لكل مستخدم عبر تطبيقات المصادقة (TOTP) مع منع إعادة استخدام الرمز، ويمكن للمدير إلغاؤه لمن فقد جهازه.
- رفع ملفات الوسائط يُبث مباشرة إلى القرص مع حد للحجم وقائمة أنواع مسموحة (لا SVG/HTML)، ويُقدَّم لمن سجّل الدخول فقط.
- قفل الحساب مؤقتاً بعد 5 محاولات فاشلة، وتحديد معدل الطلبات لكل عنوان IP.
- **الصلاحيات تُفرض على الخادم** لكل عملية كتابة (لا يمكن تجاوزها من المتصفح)، وسجلات التدقيق غير قابلة للتعديل وتُختم بهوية المستخدم وعنوانه من الخادم.
- **الوصول إلى الإنتاج والملاحظات.** يحتاج عرض البرامج والرانداون إلى صلاحيات الإنتاج. يتيح التكليف المفتوح وصولًا إلى الحلقة أو النشرة المرتبطة فقط للمكلّف باسمه أو لمالك التكليف. الملاحظات وتفضيلات مساحة العمل خاصة بحساب صاحبها عبر التطبيق، وتدخل ضمن النسخة الاحتياطية الكاملة لقاعدة البيانات.
- حماية CSRF، وسياسة CSP صارمة، وتنقية HTML المعروض (DOMPurify).
- وحدة SQL للقراءة فقط عبر اتصال منفصل، ومعطلة في الإنتاج افتراضياً.
